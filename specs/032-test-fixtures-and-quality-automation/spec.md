# Spec 032: Test Fixtures Suite, Knowledge Base & Pre-Commit Quality Automation

## 1. Мета та Контекст (Purpose & Context)
Проєкт **JE (Database Hierarchy Creator)** оперує складними ієрархічними структурами, залежними від форматування Excel-файлів, сесійних станів багатоаркушевих книг та Eel IPC мосту.
Метою даної специфікації є:
1. Створення комплексної системи еталонних тестових фікстур Excel (`.xlsx`) для перевірки крайніх випадків (edge cases).
2. Забезпечення детермінованого тестування операцій імпорту/експорту та round-trip валідації.
3. Організація єдиної бази інженерних знань проєкту ([docs/KNOWLEDGE.md](file:///e:/JE/docs/KNOWLEDGE.md)).
4. Автоматизація перевірок коду перед комітом через pre-commit хуки та оновлення [scripts/check_all.py](file:///e:/JE/scripts/check_all.py).

---

## 2. Користувацькі сценарії (User Stories)

### Сценарій 1: Надійне тестування граничних випадків Excel
* **Як** розробник/тестувальник,
* **Я хочу** мати набір готових, реалістичних Excel-файлів (`tests/fixtures/excel_samples/`) з різними конфігураціями (рвані рівні, порожні колонки, кирилиця, матриця типів даних, багатоаркушеві шаблони),
* **Щоб** автоматично перевіряти стійкість парсера та адаптера без необхідності писати громіздкий код створення Excel-файлу в кожному окремому тесті.

### Сценарій 2: Швидка валідація коду перед комітом
* **Як** розробник,
* **Я хочу** мати можливість встановити Git pre-commit hook однією командою (`python scripts/install_git_hooks.py`),
* **Щоб** бути впевненим, що будь-який зафіксований коміт відповідає `QualityGate.md` та проходить лінтери і швидкі тести.

### Сценарій 3: Довготривале збереження архітектурного контексту
* **Як** новий агент або розробник,
* **Я хочу** мати структурований документ [docs/KNOWLEDGE.md](file:///e:/JE/docs/KNOWLEDGE.md),
* **Щоб** швидко знаходити розв'язання неочевидних проблем (Eel IPC, порядок синхронізації станів, типові помилки OpenPyXL).

## 3. Функціональні вимоги (Functional Requirements)

1. **Генератор фікстур ([generate_fixtures.py](file:///e:/JE/tests/fixtures/generate_fixtures.py)):**
   * Повинен створювати 5 еталонних `.xlsx` файлів у директорії `tests/fixtures/excel_samples/`:
     * `standard_hierarchy.xlsx` — 3 рівні, регулярне заповнення, типи колонок.
     * `deep_hierarchy_ragged.xlsx` — 5-6 рівнів, неоднорідна глибина гілок, порожні проміжні клітинки.
     * `multisheet_retail.xlsx` — мінімум 3 аркуші з незалежними ієрархіями.
     * `cyrillic_and_symbols.xlsx` — назви українською мовою, апострофи, лапки, слеші, номери (`№`).
     * `data_types_matrix.xlsx` — явні типи даних (Text, Integer, Float, Boolean, Date) для кожного вузла-листа.

2. **Тестовий набір ([test_excel_fixtures.py](file:///e:/JE/tests/unit/test_excel_fixtures.py)):**
   * Повинен покривати зчитування заголовків, побудову дерева, збереження типів та round-trip експорт для кожного тестового файлу.

3. **Оновлення [check_all.py](file:///e:/JE/scripts/check_all.py):**
   * Підтримка прапорців `--quick` / `-q` (lint + format + unit + integration) та `--full` / `-f` (включно з e2e).
   * Чіткий кольоровий або структурований звіт із правильними кодами завершення (0 при успіху, 1 при помилці).

4. **Скрипт інсталяції хуків ([install_git_hooks.py](file:///e:/JE/scripts/install_git_hooks.py)):**
   * Кросплатформне створення виконуваного `.git/hooks/pre-commit` (сумісне з Windows Bash/PowerShell/Git Bash).

5. **База знань ([docs/KNOWLEDGE.md](file:///e:/JE/docs/KNOWLEDGE.md)):**
   * Опис доменних інваріантів, форматів відповідей Eel RPC, життєвого циклу аркушів та інструкцій запуску тестів.
